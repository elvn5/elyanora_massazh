# Тихо / Masajka — онлайн-запись в массажную студию

Angular 21 + Tailwind CSS 4 · Go · PostgreSQL 17 · Docker Compose · GitHub Actions.

## Что работает

- Запись в три шага: услуга и длительность 60/90/120 минут → конкретный мастер и свободное окно → контакты.
- Дополнительные опции с ценой и временем; стоимость и продолжительность рассчитывает сервер.
- Рабочие интервалы для каждого мастера по датам. Перерывы задаются промежутками между интервалами; отсутствие интервалов означает выходной.
- Слоты с шагом 15 минут, запись минимум за 30 минут, горизонт 90 дней. Время отображается в часовом поясе салона независимо от часового пояса клиента.
- Защита от накладок: транзакции, блокировка мастера и PostgreSQL GiST exclusion constraint для диапазонов `[начало, конец)`. Соседние сеансы разрешены, пересечения запрещены, в том числе при параллельных запросах.
- Подтверждение, перенос и отмена в Telegram после подключения бота; напоминания за 24 часа и за 2 часа. Если до визита меньше указанного интервала, прошедшее напоминание не создаётся.
- Персональная ссылка с криптографически случайным токеном: отмена одной кнопкой и перенос после выбора нового времени, без регистрации. Открытие ссылки само по себе ничего не отменяет.
- Telegram: `/start`, `/services`, ссылка на онлайн-запись и подключение напоминаний через персональную ссылку. Сам выбор слота выполняется на сайте.
- Админка `/admin`: пароль, серверные сессии, каталог услуг/длительностей/цен, опции, мастера, смены, записи и статусы. Статистика за выбранный день: ожидаемые и завершённые визиты, отмены, неявки и фактическая выручка.
- Изменения каталога применяются к новым записям; ранее оформленные сохраняют цену, состав и продолжительность. Все активные мастера доступны для всех услуг.

Начальные услуги и специалисты — демонстрационные данные. Рабочие интервалы автоматически **не** создаются: настройте реальные смены в админке перед приёмом клиентов. Название студии и тексты находятся в `frontend/src/app.html` и `frontend/src/admin.html`.

## Быстрый запуск в Docker

Нужны Docker Engine/Desktop и Docker Compose v2 с поддержкой `--wait`.

```sh
cp .env.example .env
# Сгенерируйте два разных секрета и запишите в POSTGRES_PASSWORD / ADMIN_PASSWORD:
openssl rand -hex 24
openssl rand -hex 24
# ADMIN_PASSWORD: 12–72 байта; POSTGRES_PASSWORD: hex / латинские буквы и цифры.
docker compose up --build -d --wait
```

- Сайт: <http://localhost:8088>
- Админка: <http://localhost:8088/admin>, пароль из `.env`.

Миграция 002 удаляет старое поле email и задания почтовой доставки, сохраняя сами записи и Telegram-уведомления.

Миграция и начальный каталог применяются при первом старте API под advisory lock. Данные PostgreSQL сохраняются в именованном volume. `docker compose down` сохраняет данные; не используйте `down -v`, если хотите их оставить.

Первые действия: войдите в админку, отредактируйте услуги и мастеров, добавьте рабочие интервалы на нужные даты. Например, 09:00–13:00 и 14:00–18:00 задают часовой перерыв. Добавляйте каждый день отдельно. Интервал с существующей записью удалить нельзя.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `PUBLIC_URL` | Точный origin сайта, без пути: например `https://booking.example.com`. Используется в сообщениях Telegram и проверке Origin. |
| `ADMIN_PASSWORD` | Пароль администратора, 12–72 байта; хешируется bcrypt при старте. |
| `ADMIN_PASSWORD_HASH` | Альтернатива для прямого запуска Go: готовый bcrypt-хеш. Имеет приоритет над паролем. |
| `SALON_TIMEZONE` | IANA timezone, по умолчанию `Asia/Bishkek`. |
| `CURRENCY` | Обозначение валюты; по умолчанию `KGS`. Цены целочисленные в основных единицах. |
| `TELEGRAM_BOT_TOKEN` | Токен бота; пустое значение отключает Telegram. |
| `WEB_BIND`, `WEB_PORT` | Адрес и порт nginx; по умолчанию только `127.0.0.1:8088`. |
| `DATABASE_URL`, `HTTP_ADDR` | Для запуска Go вне Compose. В Compose подключение к БД формируется автоматически. |

`.env` игнорируется Git и Docker build context. Не помещайте пароли в репозиторий.

### Telegram

Создайте бота через BotFather и сохраните токен в GitHub Actions Secret **`TELEGRAM_BOT_TOKEN`** (repository secret или environment `production`). CD передаст его через SSH stdin в `/opt/masajka/telegram.env` с правами 0600; токен не передаётся аргументом команды и не включается в Docker-образ. Имя бота API получает автоматически через Telegram `getMe`, с повторными попытками при сбое. Для локального запуска достаточно `TELEGRAM_BOT_TOKEN` в `.env`. Бот работает через long polling; webhook для этого токена должен быть отключён. PostgreSQL advisory lock обеспечивает один активный poller при нескольких экземплярах API. При первом подключении бот отправляет подтверждение записи и планирует оставшиеся напоминания. Повторное подключение того же чата не дублирует задания. Пользователь должен нажать «Подключить Telegram» на странице своей записи и запустить бота; до этого Telegram не может отправлять ему сообщения. Привязка относится к конкретной записи. Каталог `/services` читается из той же таблицы, что и сайт.

### Надёжность уведомлений

Очередь `jobs` создаётся в той же транзакции, что и запись. Обработчик проверяет её каждые 15 секунд, использует `FOR UPDATE SKIP LOCKED` и проверяет актуальную версию записи. При переносе старые задания заменяются; при отмене будущие напоминания удаляются. При недоступности провайдера — до 12 попыток с экспоненциальной задержкой. Ошибки видны счётчиком в админке и в журналах API. После исчерпания попыток исправьте настройки и сбросьте `attempts=0, due_at=now()` для нужных неотправленных строк в `jobs`.

Гарантия доставки — **at least once**: при сбое между приёмом сообщения Telegram и фиксацией транзакции возможен повтор. Отмена/перенос не могут отозвать уже отправленное сообщение. Время доставки зависит от доступности сервера и провайдера; очередь переживает перезапуск приложения. Секреты, тексты сообщений и токены управления в прикладные логи не выводятся.

## Локальная разработка без Docker

Нужны Node.js 24, npm, Go 1.25+ и PostgreSQL 17 с расширением `btree_gist`.

```sh
# Создайте БД masajka и пользователя с правом создания расширения btree_gist.
cd backend
export DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/masajka?sslmode=disable'
export ADMIN_PASSWORD='your-local-password'
export PUBLIC_URL='http://localhost:4200'
export HTTP_ADDR='127.0.0.1:8080'
go run .
```

В другом терминале:

```sh
cd frontend
npm ci
npm start
```

Angular проксирует `/api` на `127.0.0.1:8080`. Без токена создание записей работает, но интерфейс сообщает о недоступности бота. Уведомления создаются после привязки чата; без неё отправлять их некому. Email не запрашивается и не используется.

## Проверки

```sh
cd frontend
npm ci
npm run check
npm run build

cd ../backend
go vet ./...
go test ./...
# Интеграционные тесты требуют отдельную, только тестовую БД:
TEST_DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/masajka_test?sslmode=disable' \
  go test -race -count=1 -timeout=90s -v ./...
```

Имя тестовой БД обязательно заканчивается на `_test`. Тесты очищают таблицы записей, очереди, смен и сессий; не направляйте их на рабочую БД. Без `TEST_DATABASE_URL` интеграционные тесты явно пропускаются.

Проверяются 12 параллельных бронирований одного слота, прямой запрет пересечения в PostgreSQL, смежные записи, дополнительные минуты, границы смен, валидация контактов, перенос и снимок цены, отмена, защита админки, Origin, отзыв сессии, доставка через тестовый Telegram-транспорт, автоматическое определение имени бота, привязка и защита от повторного подключения, повторные попытки и параллельные обработчики очереди.

## CI/CD

`.github/workflows/ci.yml`: проверки типов и production-сборка Angular; Go vet, race и PostgreSQL-интеграционные тесты; сборка обоих Docker-образов. Запускается на PR и push в `main`.

`.github/workflows/cd.yml`: только после успешного CI для push в `main` собирает образы в GHCR с тегом проверенного commit SHA. Деплой включается repository variable `DEPLOY_ENABLED=true` и использует GitHub environment `production`.

Настройка сервера:

1. Linux amd64, Docker + Compose, SSH-пользователь с доступом к Docker, каталог `/opt/masajka`, принадлежащий этому пользователю.
2. Создайте `/opt/masajka/.env`: реальные секреты, `PUBLIC_URL=https://...`. Токен Telegram будет добавлен CD из GitHub Secret; указывать его в серверном `.env` не требуется. Для приватных GHCR-образов заранее выполните `docker login ghcr.io` на сервере с правом чтения пакетов.
3. Настройте DNS и HTTPS reverse proxy на `127.0.0.1:8088`. БД и API не публикуют порты наружу.
4. В GitHub добавьте secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `TELEGRAM_BOT_TOKEN`, `DEPLOY_KNOWN_HOSTS` (ключ хоста, проверенный отдельно). Не используется небезопасный `StrictHostKeyChecking=no`.
5. Push в `main` запустит пайплайн. `deploy/release.sh` выполняет pull, запуск и health checks. При ошибке пытается вернуть предыдущие образы и Compose-файл. Миграции будущих версий должны сохранять обратную совместимость; автоматического отката данных нет.

Публикация в GitHub/GHCR и на сервер требует вашего репозитория и настроек. Файлы пайплайнов подготовлены, внешний деплой из этой рабочей копии не выполнен.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка БД и API |
| GET | `/api/catalog` | Активные услуги, опции, мастера и настройки |
| GET | `/api/slots` | `date`, `specialist_id`, `service_id`, `duration`, `extras` (ID через запятую); `token` при переносе |
| POST | `/api/bookings` | Создание: `specialist_id`, `service_id`, `duration`, `extra_ids`, `starts_at` (RFC3339), `name`, `phone`, `consent` |
| GET | `/api/manage/{token}` | Данные записи |
| POST | `/api/manage/{token}/cancel` | Отмена |
| POST | `/api/manage/{token}/reschedule` | Перенос: `starts_at` |
| POST | `/api/admin/login`, `/logout` | Вход / выход, HttpOnly SameSite=Strict cookie |
| GET | `/api/admin/dashboard?date=YYYY-MM-DD` | Записи, смены, статистика, полный каталог |
| POST | `/api/admin/services`, `/extras`, `/specialists` | Создание / изменение: `id=0` для нового объекта |
| POST / DELETE | `/api/admin/shifts`, `/shifts/{id}` | Добавление / удаление рабочего интервала |
| POST | `/api/admin/bookings/{id}/status` | `cancelled`, `completed`, `no_show` |

В админке один уровень доступа. Завершить сеанс или отметить неявку можно после окончания визита. Прошедшие и закрытые записи клиент не меняет. Специалист при переносе сохраняется; для смены мастера нужно отменить запись и создать новую. Онлайн-оплата, SMS/WhatsApp, сложные повторяющиеся шаблоны смен и разграничение ролей в эту версию не входят.

## Эксплуатация

```sh
docker compose logs --tail=100 api
docker compose exec -T db pg_dump -U masajka masajka > backup.sql
# Восстановление выполняйте в подготовленную пустую БД, предварительно проверив резервную копию.
```

Настройте внешнее резервное копирование, мониторинг `/api/health` и очереди ошибок. При HTTPS включаются Secure cookies. Nginx ограничивает запросы к API и не пишет персональные URL API в access log. Reverse proxy перед nginx тоже должен исключать токены и query string из своих журналов. Удаление устаревших сессий и срок хранения персональных данных задаются эксплуатационными регламентами салона.
