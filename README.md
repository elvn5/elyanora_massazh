# Elyanora / Masajka — онлайн-запись в массажную студию

Angular 21 + Tailwind CSS 4 · Go · PostgreSQL 17 · Docker Compose · GitHub Actions.

## Что работает

- Вся клиентская запись проходит внутри Telegram по кнопкам: услуга → 60/90/120 минут → дополнительные опции → мастер → свободная дата и время → имя и телефон → согласие и подтверждение.
- Дополнительные опции с ценой и временем; стоимость и продолжительность рассчитывает сервер.
- Рабочие интервалы для каждого мастера по датам. Перерывы задаются промежутками между интервалами; отсутствие интервалов означает выходной.
- Слоты с шагом 15 минут, запись минимум за 30 минут, горизонт 90 дней. Время отображается в часовом поясе салона независимо от часового пояса клиента.
- Защита от накладок: транзакции, блокировка мастера и PostgreSQL GiST exclusion constraint для диапазонов `[начало, конец)`. Соседние сеансы разрешены, пересечения запрещены, в том числе при параллельных запросах.
- Подтверждение, перенос и отмена в Telegram с кнопками управления визитом; напоминания за 24 часа и за 2 часа. Если до визита меньше указанного интервала, прошедшее напоминание не создаётся.
- «Мои записи»: предстоящие визиты, перенос с выбором нового окна и отмена с подтверждением. Доступ проверяется по Telegram ID владельца при каждом действии.
- Telegram: `/start`, `/book`, `/bookings`, `/services`, `/menu`. Кнопки, запрос своего контакта, страницы каталога и свободных окон. Старые кнопки проверяются по версии диалога/записи.
- Веб содержит только админку (`/` и `/admin`): пароль, серверные сессии, каталог услуг/длительностей/цен, опции, мастера, смены, записи и статусы. Статистика за выбранный день: ожидаемые и завершённые визиты, отмены, неявки и фактическая выручка.
- Изменения каталога применяются к новым записям; ранее оформленные сохраняют цену, состав и продолжительность. Все активные мастера доступны для всех услуг.

Начальные услуги и специалисты — демонстрационные данные. Рабочие интервалы автоматически **не** создаются: настройте реальные смены в админке перед приёмом клиентов. Приветствие и контакты бота меняются в разделе Telegram-бот.

## Быстрый запуск в Docker

Нужны Docker Engine/Desktop и Docker Compose v2 с поддержкой `--wait`.

```sh
cp .env.example .env
# Сгенерируйте два разных секрета и запишите в POSTGRES_PASSWORD / ADMIN_PASSWORD:
openssl rand -hex 24
openssl rand -hex 24
# ADMIN_PASSWORD: 12–72 байта; POSTGRES_PASSWORD: hex / латинские буквы и цифры.
docker compose up --build -d --wait
```

- Админка: <http://localhost:8088/admin>, пароль из `.env`.

Миграция 002 удаляет старое поле email и задания почтовой доставки, сохраняя сами записи и Telegram-уведомления.

Миграция и начальный каталог применяются при первом старте API под advisory lock. Данные PostgreSQL сохраняются в именованном volume. `docker compose down` сохраняет данные; не используйте `down -v`, если хотите их оставить.

Первые действия: войдите в админку, отредактируйте услуги и мастеров, добавьте рабочие интервалы на нужные даты. Например, 09:00–13:00 и 14:00–18:00 задают часовой перерыв. Добавляйте каждый день отдельно. Интервал с существующей записью удалить нельзя.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `PUBLIC_URL` | Точный origin сайта, без пути: например `https://booking.example.com`. Используется для проверки Origin в админке. Клиентских ссылок на сайт бот не отправляет. |
| `ADMIN_PASSWORD` | Пароль администратора, 12–72 байта; хешируется bcrypt при старте. |
| `ADMIN_PASSWORD_HASH` | Альтернатива для прямого запуска Go: готовый bcrypt-хеш. Имеет приоритет над паролем. |
| `SALON_TIMEZONE` | IANA timezone, по умолчанию `Asia/Bishkek`. |
| `CURRENCY` | Обозначение валюты; по умолчанию `KGS`. Цены целочисленные в основных единицах. |
| `TELEGRAM_BOT_TOKEN` | Токен бота; пустое значение отключает Telegram. |
| `WEB_BIND`, `WEB_PORT` | Адрес и порт nginx; по умолчанию только `127.0.0.1:8088`. |
| `DATABASE_URL`, `HTTP_ADDR` | Для запуска Go вне Compose. В Compose подключение к БД формируется автоматически. |

`.env` игнорируется Git и Docker build context. Не помещайте пароли в репозиторий.

### Telegram

Создайте бота через BotFather и сохраните токен в GitHub Actions Secret **`TELEGRAM_BOT_TOKEN`** (repository secret или environment `production`). CD передаст его через SSH stdin и ограниченный `deploy/ssh-gateway.sh` в `/opt/masajka/telegram.env` с правами 0600; токен не передаётся аргументом команды и не включается в Docker-образ. Имя бота API получает автоматически через Telegram `getMe`, с повторными попытками при сбое. Для локального запуска достаточно `TELEGRAM_BOT_TOKEN` в `.env`. Бот работает через long polling; webhook для этого токена должен быть отключён. PostgreSQL advisory lock обеспечивает один активный poller при нескольких экземплярах API. Клиент запускает бота и оформляет визит внутри диалога. Telegram ID сохраняется вместе с записью, поэтому подтверждение и напоминания подключаются автоматически. Услуги, мастера и опции читаются из каталога админки. Отключение «Услуги и цены» скрывает отдельный обзор каталога, но сохраняет выбор услуги при записи. Ссылки `/start <token>` для старых записей по-прежнему привязывают чат, а управление продолжается внутри бота.

Миграция 005 добавляет сессии диалогов и квитанции обработанных Telegram update_id. Запись, очередь уведомлений, состояние диалога и квитанция сохраняются одной транзакцией. Повтор update_id или повторное нажатие старой кнопки не создаёт второй визит. Выбор переживает перезапуск сервера и истекает через 24 часа бездействия; технические сессии очищаются через 30 дней, квитанции — через 7 дней. Стоимость и доступность окна повторно проверяются при подтверждении; новая цена требует повторного согласия. При переносе сохраняются услуга, мастер, продолжительность и исходная стоимость.

### Надёжность уведомлений

Очередь `jobs` создаётся в той же транзакции, что и запись. Обработчик проверяет её каждые 15 секунд, использует `FOR UPDATE SKIP LOCKED` и проверяет актуальную версию записи. При переносе старые задания заменяются; при отмене будущие напоминания удаляются. При недоступности провайдера — до 12 попыток с экспоненциальной задержкой. Ошибки видны счётчиком в админке и в журналах API. После исчерпания попыток исправьте настройки и сбросьте `attempts=0, due_at=now()` для нужных неотправленных строк в `jobs`.

Гарантия доставки — **at least once**: при сбое между приёмом сообщения Telegram и фиксацией транзакции возможен повтор. Отмена/перенос не могут отозвать уже отправленное сообщение. Время доставки зависит от доступности сервера и провайдера; очередь переживает перезапуск приложения. Секреты, тексты сообщений и токены управления в прикладные логи не выводятся.

## Локальная разработка без Docker

Нужны Node.js 24, npm, Go 1.25+ и PostgreSQL 17 с расширением `btree_gist`.

```sh
# Создайте БД masajka и пользователя с правом создания расширения btree_gist.
cd backend
export DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/masajka?sslmode=disable'
export ADMIN_PASSWORD='your-local-password'
export PUBLIC_URL='http://localhost:4200'
export HTTP_ADDR='127.0.0.1:8080'
go run .
```

В другом терминале:

```sh
cd frontend
npm ci
npm start
```

Angular проксирует `/api` на `127.0.0.1:8080`. Без токена работает админка, клиентская запись через Telegram недоступна. Для локальных тестов используется поддельный транспорт Telegram, реальные сообщения не отправляются. Email не запрашивается и не используется.

## Проверки

```sh
cd frontend
npm ci
npm run check
npm run build

cd ../backend
go vet ./...
go test ./...
# Интеграционные тесты требуют отдельную, только тестовую БД:
TEST_DATABASE_URL='postgres://USER:PASSWORD@127.0.0.1:5432/masajka_test?sslmode=disable' \
  go test -race -count=1 -timeout=90s -v ./...
```

Имя тестовой БД обязательно заканчивается на `_test`. Тесты очищают таблицы записей, очереди, смен и сессий; не направляйте их на рабочую БД. Без `TEST_DATABASE_URL` интеграционные тесты явно пропускаются.

Дополнительно проверяются полный диалог бота, восстановление сессии, повторные update_id, устаревшие кнопки, чужой контакт, доступ другого чата, конкурентное подтверждение, изменение цены, перенос, отмена и кнопки в уведомлениях.

Проверяются 12 параллельных бронирований одного слота, прямой запрет пересечения в PostgreSQL, смежные записи, дополнительные минуты, границы смен, валидация контактов, перенос и снимок цены, отмена, защита админки, Origin, отзыв сессии, доставка через тестовый Telegram-транспорт, автоматическое определение имени бота, привязка и защита от повторного подключения, повторные попытки и параллельные обработчики очереди.

## CI/CD

`.github/workflows/ci.yml`: проверки типов и production-сборка Angular; Go vet, race и PostgreSQL-интеграционные тесты; сборка обоих Docker-образов. Запускается на PR и push в `main`.

`.github/workflows/cd.yml`: только после успешного CI для push в `main` собирает образы в GHCR с тегом проверенного commit SHA. Деплой включается repository variable `DEPLOY_ENABLED=true` и использует GitHub environment `production`.

Настройка сервера:

1. Linux amd64, Docker + Compose, SSH-пользователь с доступом к Docker, каталог `/opt/masajka`, принадлежащий этому пользователю.
2. Создайте `/opt/masajka/.env`: реальные секреты, `PUBLIC_URL=https://...`. Токен Telegram будет добавлен CD из GitHub Secret; указывать его в серверном `.env` не требуется. CD передаёт краткоживущий `GITHUB_TOKEN` с `packages:read` через SSH stdin; временная конфигурация Docker удаляется после деплоя.
3. Настройте DNS и HTTPS reverse proxy на `127.0.0.1:8088`. БД и API не публикуют порты наружу.
4. Установите `deploy/release.sh` как `/opt/masajka/release.sh`, `deploy/ssh-gateway.sh` как `/opt/masajka/ssh-gateway.sh` с правами 0700. Добавьте отдельный публичный ключ деплоя в `authorized_keys` с префиксом `restrict,command="/opt/masajka/ssh-gateway.sh"`. Ключ не даёт интерактивную оболочку и принимает только команды деплоя этого приложения. Обновления этих двух серверных скриптов выполняйте через административный SSH-доступ.
5. В GitHub добавьте secrets: `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_SSH_KEY`, `TELEGRAM_BOT_TOKEN`, `DEPLOY_KNOWN_HOSTS` (ключ хоста, проверенный отдельно). Не используется небезопасный `StrictHostKeyChecking=no`.
6. Push в `main` запустит пайплайн. `deploy/release.sh` выполняет pull, запуск и health checks. При ошибке пытается вернуть предыдущие образы и Compose-файл. Миграции будущих версий должны сохранять обратную совместимость; автоматического отката данных нет.

Публикация в GHCR и деплой запускаются автоматически после успешного CI в `main` при `DEPLOY_ENABLED=true`.

## API

Все методы, кроме health и login, требуют сессию администратора. Публичные клиентские API удалены; бот вызывает серверную логику напрямую.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка БД и API |
| GET | `/api/admin/catalog` | Активные услуги, опции, мастера и настройки |
| GET | `/api/admin/slots` | `date`, `specialist_id`, `service_id`, `duration`, `extras` (ID через запятую); `token` при переносе |
| POST | `/api/admin/bookings` | Создание: `specialist_id`, `service_id`, `duration`, `extra_ids`, `starts_at` (RFC3339), `name`, `phone`, `consent` |
| GET | `/api/admin/manage/{token}` | Данные записи |
| POST | `/api/admin/manage/{token}/cancel` | Отмена |
| POST | `/api/admin/manage/{token}/reschedule` | Перенос: `starts_at` |
| POST | `/api/admin/login`, `/logout` | Вход / выход, HttpOnly SameSite=Strict cookie |
| GET | `/api/admin/dashboard?date=YYYY-MM-DD` | Записи, смены, статистика, полный каталог |
| POST | `/api/admin/services`, `/extras`, `/specialists` | Создание / изменение: `id=0` для нового объекта |
| POST / DELETE | `/api/admin/shifts`, `/shifts/{id}` | Добавление / удаление рабочего интервала |
| POST | `/api/admin/bookings/{id}/status` | `cancelled`, `completed`, `no_show` |

В админке один уровень доступа. Завершить сеанс или отметить неявку можно после окончания визита. Прошедшие и закрытые записи клиент не меняет. Специалист при переносе сохраняется; для смены мастера нужно отменить запись и создать новую. Онлайн-оплата, SMS/WhatsApp, сложные повторяющиеся шаблоны смен и разграничение ролей в эту версию не входят.

## Эксплуатация

```sh
docker compose logs --tail=100 api
docker compose exec -T db pg_dump -U masajka masajka > backup.sql
# Восстановление выполняйте в подготовленную пустую БД, предварительно проверив резервную копию.
```

Настройте внешнее резервное копирование, мониторинг `/api/health` и очереди ошибок. При HTTPS включаются Secure cookies. Nginx ограничивает запросы к API и не пишет персональные URL API в access log. Reverse proxy перед nginx тоже должен исключать токены и query string из своих журналов. Удаление устаревших сессий и срок хранения персональных данных задаются эксплуатационными регламентами салона.

Для совместного сервера Compose ограничивает память контейнеров (БД 512 МБ, API 256 МБ, web 128 МБ), CPU и объём журналов. Деплой явно использует проект `masajka`; команды очистки или остановки других проектов не выполняются.

## Общая цветовая схема

Все цвета админки заданы в `frontend/src/theme.css` как семантические Tailwind/CSS-переменные. Основной акцент — тёмно-зелёный, выделения — шалфейные, фон — светлый. Используйте `var(--color-brand)`, `var(--color-surface)`, `var(--color-muted)` и другие токены вместо отдельных HEX-цветов в компонентах. Цвета ошибок, успеха и неактивных статусов также общие. Нативные элементы форм используют светлую схему.

Production-сборка подключает CSS обычным `link rel="stylesheet"`, без встроенного `onload`, который блокируется CSP. `npm run build` проверяет это через `scripts/check-styles.mjs`, а также наличие общей темы и стилей админки. Не включайте `optimization.styles.inlineCritical` без совместимого с CSP механизма загрузки CSS.

## Рабочее пространство администратора

`/admin` открывает отдельную панель с боковым меню: дашборд, записи, расписание, услуги, дополнительные опции, специалисты и Telegram-бот. На телефоне меню выдвигается по кнопке. Раздел сохраняется в адресе страницы.

Дашборд показывает реальные записи и выручку завершённых сеансов за выбранный день, рабочие часы команды и число записей за последние семь дней в часовом поясе салона. В разделе записей доступны поиск и фильтр статуса.

В настройках бота можно изменить приветствие, контактный текст, доступность команды `/services` и отдельно включить напоминания за 24 и 2 часа. Настройки хранятся в PostgreSQL (миграция 003) и применяются без перезапуска. Отключённые напоминания удаляются из очереди при наступлении времени отправки; после включения пропущенные сообщения не догоняются. Подтверждения, отмены и переносы продолжают работать. Токен остаётся в GitHub Secrets и не возвращается через API. Проверка подключения вызывает только Telegram `getMe`.

Защищённые API: `GET/PUT /api/admin/bot`, `POST /api/admin/bot/check`, `POST /api/admin/bot/retry`. Повторная отправка возвращает в обработку только актуальные задания с ошибкой. Панель показывает очередь, ошибки, отправки за семь дней и привязанные будущие записи.
